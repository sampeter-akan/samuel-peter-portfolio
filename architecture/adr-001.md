# ADR-001 — Deterministic diagnostic fallback alongside Gemini
Recorded: 10 November 2026. Scope: GridPulse Enterprise simulation. Status: implemented pattern, documented from source; not a retrospective approval record.
## Context
The diagnostic workflow should remain usable when the AI dependency or diagnostics endpoint is unavailable. Reviewers must be able to distinguish AI synthesis from deterministic rule output.
## Decision and implementation
The client posts a structured snapshot to /api/diagnostics. A successful HTTP response is returned as a diagnostic report. On request failure or a non-success HTTP response, the client invokes generateDeterministicDiagnostic. The Express server attempts Gemini when a key is configured and falls back to its own rules when generation fails or no key is present. The advisor labels the mode from isAiGenerated.
## Options and trade-offs
1. AI-only: richer narrative, but a dependency failure can remove the report.
2. Rules-only: reproducible for covered scenarios, but limited to maintained rules.
3. Combined approach, implemented: preserves a diagnostic path, with additional rule maintenance and consistency obligations.
Cost assessment is qualitative: AI calls introduce usage and latency costs; rules introduce engineering and regression-maintenance costs. No cost or latency benchmark is claimed.
## Consequences and review conditions
A fallback response is not proof of diagnosis correctness. Client and server rules must be compared: the client has an under-frequency branch that is absent from the server fallback. Fetch has no explicit client timeout, and successful response JSON is not runtime schema-validated in this client service. Treat these as release-review items, not resolved controls.
## Acceptance checks
Exercise AI success, missing configuration, endpoint failure, non-success HTTP, malformed JSON and delayed responses. Compare identical snapshots across both rule paths; show mode and region in each assessment. Retain operator review of recommendations.
