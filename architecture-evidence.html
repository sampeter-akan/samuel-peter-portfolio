ADR-001 · Implemented pattern

Deterministic fallback alongside Gemini

Decision: retain a rule-based diagnostic path when the AI dependency or diagnostics request is unavailable, and distinguish the report mode in the interface.

Trade-off: AI-only increases dependency exposure; rules-only limits coverage. Combining them preserves a diagnostic path while adding rule-consistency and maintenance obligations.

Source evidence: the client posts to /api/diagnostics and uses local rules on failure; the server attempts Gemini when configured and otherwise uses server rules. The advisor displays AI or deterministic mode.

Review finding: client and server fallback coverage differs. Client request timeouts and runtime response validation also need assurance. See EX-001; these controls are not represented as resolved.

Exception & design-risk register

EX-001 · Fallback rule consistency

Open review item: the client has an under-frequency branch absent from the server fallback. The same snapshot can therefore be classified differently depending on the executing path.

Release condition: align the rule paths or document deliberate differences, then compare shared regression fixtures. A maintainer must assign the owner and remediation date at review; no waiver or closure is recorded here.

The reusable register captures rationale, accountable owner, approval authority, remediation date, compensating controls and closure evidence.
